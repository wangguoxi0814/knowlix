# Knowlix 需求说明

> 版本：0.4（**完整产品需求**，不拆分为可执行任务单元）  
> 关联文档：[TECHNICAL_DESIGN.md](./TECHNICAL_DESIGN.md)

---

## 1. 文档目的与范围

本文档描述 Knowlix 在「**知识图谱管理单词与词组**」以及「**检验闭环**」方向上的**业务目标、功能需求、关键规则、数据语义与非功能期望**，供产品、设计与研发对齐。**不包含**按迭代拆分的可执行条目、工期估算或验收工单编号；实施拆解由项目管理或单独排期文档承担。

**范围**：总词汇知识图谱、单次学习的子图学习集（约 10～20 项）、两种检验模式（用户造句、系统出题）、录入时相似合并与出现次数统计、掌握状态与界面反馈（移除感/划掉）。  

**范围外（除非另行追加需求）**：具体商业 ASR 厂商选定、SRS 算法细节、多语言全面词形变化表、大规模图可视化美术规范、合规与法务定稿。

**技术约束（与实现对齐）**：**总词汇知识图谱**（节点、边、出现次数）持久化于 **Neo4j**；**用户掌握状态**、子图会话快照、合并审计等关系型数据持久化于 **PostgreSQL**；二者以词汇节点 **UUID** 关联，不依赖跨库外键。

## 2. 背景与问题陈述

学习者面对的词库规模往往持续增长，若始终以「全量图谱」作为学习与检验单位，会导致：

- **认知过载**：节点与边数量超出工作记忆与单次会话可处理范围。  
- **交互成本过高**：检索、选题、浏览关系网络的耗时上升，学习动机下降。  
- **检验难以聚焦**：题目来源发散，无法与当前学习目标强绑定。

因此产品将「**总知识图谱**」作为权威底库，将「**单次学习可用的最小子图**」作为默认学习单元，并在检验后将已掌握内容从**当前练习语境**中移除或以**划掉**形式呈现，从而形成可完成、可感知进步的学习闭环。

同时，录入端存在大量**近似重复**（拼写变体、空格差异、极近义表达），若全部建成独立节点会稀释统计与采样权重。需要通过**相似合并**与**出现次数**体现「被反复触及的重点」。

## 3. 术语表

| 术语 | 定义 |
|------|------|
| **总知识图谱** | 系统内全量单词、词组节点及其边的集合；随录入、合并、人工维护而演进，是数据的权威来源。 |
| **节点** | 图谱中的基本单位，类型至少包括 **单词**、**词组**；每个节点有稳定唯一标识与对外展示的**规范形**文本。 |
| **边** | 连接两个节点的关系，带有**关系类型**（如搭配、上下位、共现、翻译对等，具体枚举以技术设计为准），可含权重或说明性元数据。 |
| **子知识图谱 / 最小学习集** | 从总图谱中按策略抽取的一组节点（目标规模 **10～20**，允许产品配置上下界）及其间相关边构成的、用于**当前学习会话**的子结构。 |
| **掌握** | 系统判定用户对某一规范节点已达到要求的学习状态；掌握后该节点不应再作为**未掌握必练项**出现在当前会话的强制练习列表中（见第 6 章）。 |
| **待练集合** | 某次学习会话中，尚未被判定为掌握的节点集合（通常由子图初始化，并随检验结果收缩）。 |
| **合并** | 新录入内容与已有节点相似度过高时，不新建独立规范节点，而是归入已有**规范节点**，并累计统计次数。 |
| **出现次数 / 合并次数** | 反映该规范节点被重复录入、命中合并或等价触达的频率，用于**重点排序**、子图采样加权等（具体公式由技术设计给出，需求侧要求「单调、可解释、可审计」）。 |

## 4. 产品目标与用户价值

### 4.1 产品目标

1. 以**知识图谱**统一承载单词、词组及其关系，避免词汇与关系散落在互不关联的列表中。  
2. 任意时刻为学习者提供**规模可控**（约 10～20 项）的**子图学习集**，使单次学习会话可完成、可复盘。  
3. 通过**两种互补的检验方式**（主动造句 vs 系统出题）巩固记忆，并将**已掌握**内容从当前练习流中清退，给予明确正向反馈。  
4. 在持续录入中**抑制冗余节点**、通过**频次**凸显重点，使学习与出题更贴近真实使用强度。

### 4.2 目标用户与典型场景

- **自主语言学习者**：自建词库与搭配关系，希望每次专注一小块关联词汇。  
- **备考/强化训练**：需要在有限时间内高密度检验，且希望已掌握项不再占用注意力。  
- **内容维护者**：批量或持续录入，希望系统自动合并近似项并保留「有多常被录入」的信号。

## 5. 功能需求

### 5.1 总知识图谱管理

**5.1.1 节点管理**

- 系统应支持创建、查看、编辑（在权限允许范围内）、删除或归档**单词**与**词组**节点。  
- 每个节点必须具备**规范形**（用于展示与匹配的主文本），并可扩展可选属性（如音标、简短释义、备注）；具体字段以数据模型为准，需求层要求**规范形在同一类型内唯一或可解析冲突**（技术设计定义冲突策略）。  
- 节点删除或归档时，应定义**关联边**与**子图历史**的处理原则（级联删除、禁止删除若存在依赖、或软删除），避免产生不可解释的悬挂引用。

**5.1.2 边与关系管理**

- 系统应支持在节点之间创建、查看、编辑、删除**有向或双向**关系（方向性以产品枚举为准），并携带**关系类型**。  
- 应支持同一对节点存在**多条不同类型**的边（若产品允许），或明确禁止重复边并给出用户可理解的提示。  
- 应提供基础的**一致性校验**（如禁止自环、限制非法类型组合等，以技术设计列举为准）。

**5.1.3 总图与学习的关系**

- **总知识图谱**是全局底库；**学习会话**默认不直接以全图为操作界面，而是通过下一节的子图机制承载「当前学什么」。  
- 系统应能基于总图回答：**某节点及其邻居是谁**、**某用户对该节点的掌握情况**、**该节点的出现次数与合并历史摘要**（至少对维护者或调试可见）。

---

### 5.2 子知识图谱（最小学习集）与「过大」问题

**5.2.1 问题定义**

- 当总图中节点数量很大时，产品**不得**要求用户在无筛选条件下一次性消化全图。  
- 默认交互应以「**本次学习的子图**」为主视图或主列表来源。

**5.2.2 子图规模**

- 每次为用户生成的子图，节点数量应在 **10～20** 的区间内（**可配置**最小值与最大值；全库不足上限时允许少于下限并给出说明）。  
- 子图应包含与这些节点**学习相关**的边（例如诱导子图，或「扩展一跳邻居」的策略之一；由技术设计固定并在界面简要说明，避免用户困惑）。

**5.2.3 采样策略（需求级描述）**

- 子图生成应支持**随机性**（避免用户永远见到同一批词），同时宜支持以下**至少一类**偏向策略（可多选叠加，具体算法实现不在本文约束）：  
  - 优先包含**未掌握**或**掌握程度低**的节点；  
  - 在同类候选中，对**出现次数高**的节点赋予更高被选概率（体现重点）；  
  - 可选：围绕用户选择的**主题**、**种子节点**或**某条边**展开子图。  
- 用户应能**重新生成**子图（新随机种子或新会话），且行为符合预期（旧会话的未保存掌握状态应有明确提示策略，见非功能与体验）。

**5.2.4 输出与下游**

- 子图生成结果应能驱动：**列表展示**、**简易关系可视化**（若有）、**两种检验模式**的题目来源范围（**不得**从未包含在子图中的节点出题，除非产品明确允许「拓展题」类功能，本版默认不允许）。

---

### 5.3 检验（掌握闭环）

检验模块的核心是：**依据当前子图**组织练习，并在判定掌握后，使该项在**当前学习语境**中表现为**已清退**（从待练集合移除）或**已划掉**，并与持久化的**掌握状态**一致。

**5.3.1 掌握状态语义**

- 系统应维护用户对规范节点的掌握信息，至少区分：**未掌握 / 学习中 / 已掌握**（状态命名可调整，语义需覆盖这三种差别）。  
- **已掌握**节点：  
  - 在**当前子图会话**的待练列表中移除，或在 UI 上以**划掉**形式显示且不再作为必答题目标；  
  - 在**后续子图采样**中可被策略「排除」或「降权」（需求建议默认排除已掌握，除非用户显式选择复习模式）。  
- 状态变更应带**时间戳**与**最近一次检验方式**（造句 / 出题），便于统计与复盘。

**5.3.2 模式一：用户自行造句**

- 用户应能通过**键盘输入**完成造句；**语音输入**为增强能力：若启用，系统应将语音转为文本后再进入同一套判定流程。  
- 系统应向用户明确**当前需覆盖的目标**（可为单目标或多目标；多目标时需定义「全部覆盖」还是「覆盖其一」——本版建议默认**每轮单目标**以降低歧义，多目标为可选增强）。  
- **合格判定**应可配置严格程度，但需求层必须满足：  
  - **误判为合格**的概率应可控（即「未覆盖却说覆盖」不可接受）；**误判为不合格**时可接受一定冗余，但应给出可理解的反馈（例如未检测到目标词形）。  
- 判定合格后：更新掌握状态，并使该目标从**当前待练集合**移除（或等价 UI 效果）；**「从库里移除以掌握知识」** 在本产品中解释为：**从当前必练与未掌握集合中移除**，**不**强制要求物理删除总图节点（除非产品另行定义「删除已掌握词」的独立功能）。

**5.3.3 模式二：系统根据子图定制出题**

- 系统应能基于**当前子知识图谱**自动生成题目（题型可包含选择、填空、连线、听写等；MVP 至少一种可端到端完成）。  
- 题目所考察的知识点应**来源于子图节点或边**，与用户当前会话上下文一致。  
- 用户作答后，系统应判定正误并更新掌握状态（掌握规则需定义：如「连续正确 N 次」或「单次测验达阈值」；本版由技术设计与产品共同拍板，需求要求**规则对用户可解释**）。  
- 对已掌握项：在题目列表或词汇列表中**划掉**展示，并在后续出题中**排除或显著降权**，保证用户能感知「这一部分已经过关」。

**5.3.4 模式并存与编排**

- 两种模式可在同一学习会话中并存（例如分栏、分步骤或 Tab），具体信息架构由 UI 设计决定；需求要求**状态一致**：无论从哪种模式达成掌握，待练集合与划掉展示应统一更新。

---

### 5.4 单词/词组录入与相似合并、重点区分

**5.4.1 录入**

- 用户应能提交新词或词组文本，并指定类型（单词/词组）；系统应进行**归一化**（大小写、空白、常见全半角等），以减少无意义重复。  
- 录入成功后，总图中应可检索到该规范节点或其所合并到的目标节点。

**5.4.2 相似合并**

- 在录入时，系统应将新内容与已有节点进行**相似度比较**；当相似度**高于阈值**时，应执行**合并**到选定已有规范节点，而非创建新节点。  
- 合并结果对用户可见：**明确展示**将合并到哪一个已有词/词组，避免静默吞并引发不信任。  
- 应保留**可追溯信息**（如别名、原始输入、合并时间、相似度分数或档位），以支持纠错与客服/调试（详细保留策略由技术设计与隐私策略约束）。

**5.4.3 出现次数与重点**

- 每次触发合并或「同一规范节点的等价重复录入」时，应增加与该节点关联的**出现次数**（或等价计数器），用于：  
  - 列表或词库视图中的**默认排序权重**；  
  - 子图采样时的**加权**（高频更可能被抽入学习集）；  
  - 可选的「重点」标签或筛选。  
- 计数应**单调不减**（除非管理员执行合法的回滚或拆分操作），且能说明**最后一次递增的来源**（录入、导入、合并）。

**5.4.4 误合并处理（期望能力）**

- 产品应预期存在误合并；宜提供**人工拆分**或**强制新建不合并**的路径（优先级可作为 P1，但需求文档中明确为**质量保障**所需能力，避免长期数据污染）。

## 6. 业务规则与一致性（跨模块）

1. **子图边界**：检验所依据的「当前词表」默认等于**当前子图节点集合**与**待练集合**的交集相关规则；不得从子图外偷偷加入必考项而不告知用户。  
2. **掌握与总图**：掌握状态绑定**规范节点**；合并后，所有别名应解析到同一掌握记录（或同步规则一致）。  
3. **随机与可复现**：若需支持「复现某次学习」或调试，应能通过会话标识或种子复现子图（可选能力，不影响默认随机体验）。  
4. **空库与边界**：总图为空或可采样节点不足时，系统应给出明确引导（引导录入或降低子图下限），不得崩溃或无反馈。  
5. **并发**：多设备或多标签同时学习同一用户时，应有合理冲突策略（最后写入 wins、或会话隔离）；至少保证**单会话内**状态自洽。

## 7. 用户界面与体验（需求级）

- **子图页**：展示本次 10～20 个词/词组及关系摘要；支持刷新子图。  
- **检验页**：清晰展示模式一（造句）与模式二（出题）的入口与当前目标；划掉样式明显且不依赖单一颜色（考虑色弱）。  
- **录入页**：展示合并预览与出现次数变化。  
- **错误与降级**：ASR 不可用时应提示并允许纯键盘继续；LLM 不可用时应能降级到规则出题/子串覆盖（与技术设计一致）。

## 8. 非功能需求（摘要）

| 类别 | 期望 |
|------|------|
| **性能** | 子图生成与一次出题在常规数据量下应在用户可接受时间内完成（具体数值由技术设计结合目标数据规模补充）。 |
| **可靠性** | 掌握状态、计数递增、合并操作应具备事务性或等价一致性，避免重复提交导致计数错误。 |
| **可测试性** | 覆盖判定、状态机、采样在随机种子固定下应可自动化测试。 |
| **安全与隐私** | 语音与文本可能含敏感内容；存储周期、访问控制与脱敏在运维/安全方案中定义；需求要求**密钥与配置不入库、不进领域层代码**。 |
| **可访问性** | 核心流程可通过键盘完成；语音为可选增强。 |

## 9. 假设与依赖

- 用户具备基础文本输入能力；语音能力依赖设备麦克风与浏览器或客户端能力。  
- 「相似度阈值」「掌握判定阈值」等参数需要初版默认值与后续调参机制，但不阻塞 MVP 闭环，由技术设计给出默认与配置入口。  
- 若未来接入账号体系，用户标识从匿名会话升级为正式用户时，需定义掌握数据迁移规则（可在账号功能需求中单独立项）。

---

## 10. 成功标准（产品层）

在不做可执行任务拆分的前提下，产品达到「可对外演示的 MVP」应满足：

1. 能维护一份可用的**总词汇知识图谱**（节点 + 边）。  
2. 能一键生成 **10～20** 项的**子图学习集**并展示。  
3. **模式二**至少一种题型可基于子图完整跑通，且已掌握项在界面**划掉**并与数据一致。  
4. **模式一**至少键盘造句可跑通，通过后该项从当前必练中消失。  
5. **录入合并 + 出现次数** 在合并与重复录入场景下表现正确，并可被用户感知（排序或标签至少一种）。
